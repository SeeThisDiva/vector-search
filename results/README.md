# Results & Benchmark Artifacts Index

All committed benchmark outputs, design specifications, gate sign-offs, and deterministic charts live under `results/` (whereas raw SIFT corpora and local caches stay gitignored under `data/`). Phase 4 through Phase 7 reports (and `results/phase3/phase2_report.json`) record `git_commit` and `"git_dirty": false`; earlier Phase 3 and Phase 3.5 reports predate those provenance fields and are traced to their generating and committing Git hashes in `results/CLAIMS.md`.

## Canonical Audit Ledger

- **[`CLAIMS.md`](./CLAIMS.md)** — Authoritative claim-verification ledger mapping every documented metric across `README.md` and phase reports to its exact source JSON file, JSON key path, serialized value, generating Git commit, and host environment.

## Artifact Conventions

- **Raw `.json` Reports (`scale_*`, `cell_*`, `arm_*`, `rust_*`, `faiss_*`, `summary*`)**: Phase 4 through Phase 7 reports (plus `phase3/phase2_report.json`) are stamped with `git_commit`, `git_dirty: false`, `hardware`, `environment` (OS power plan, CPU affinity mask), and sweep distributions. Earlier Phase 3 and Phase 3.5 reports (`phase3_report.json`, `baseline_profile_report.json`, `baseline_1m_report.json`, `exp_no_keep_pruned_shrink_*.json`, `final_1m_report.json`, `golden_*.json`) predate `git_commit`/`git_dirty` fields and are traced to their Git commits in [`CLAIMS.md`](./CLAIMS.md).
- **Design & Gate Docs (`DESIGN.md`, `G*_DECISIONS.md`, `PROPOSAL.md`, `FINDINGS.md`)**: Pre-implementation specs (`DESIGN.md`), gate sign-offs (`G*_DECISIONS.md`), pilot-anchored time/disk budgets (`PROPOSAL.md`), and post-run empirical analyses (`FINDINGS.md`).
- **`pilot/` & `smoke/`**: Single-point or microbenchmark runs used to calibrate budgets (`pilot/`) and fast `10k` end-to-end verification runs (`smoke/`).
- **Root Charts vs `charts_100k/` & `charts_1m/`**: Per-scale PNG (300 DPI) and SVG plots live under `charts_100k/` and `charts_1m/` in Phases 5–7. In `phase5/` and `phase6/`, root charts copy the `1M` headline set; in `phase7/`, root `chart1`–`chart3` present combined `100k` + `1M` side-by-side overview panels while root `chart4` mirrors `charts_1m/chart4_multithread_and_build`.
- **README Summary Charts**: [`hero_recall_vs_latency.png`](./hero_recall_vs_latency.png) ([SVG](./hero_recall_vs_latency.svg)) and [`filter_collapse.png`](./filter_collapse.png) ([SVG](./filter_collapse.svg)), regenerated directly from tracked JSONs via [`scripts/plot_hero.py`](../scripts/plot_hero.py) and [`scripts/plot_filter_collapse.py`](../scripts/plot_filter_collapse.py).
